<objective>
Implement the end-to-end training and evaluation pipeline for TQC:
1. Structured Metrics Logger (`src/tqc/logger.py`) capturing training diagnostics, evaluation returns, losses, alpha, and Q quantile distribution statistics into CSV and JSONL formats (EXP-02).
2. Deterministic policy evaluation runner (`src/tqc/evaluate.py`) running 10 test episodes with deterministic action selection ($a = \tanh(\mu)$) and reporting mean and standard deviation of episodic returns (EXP-01).
3. End-to-end Training Pipeline (`src/tqc/train.py`) orchestrating buffer warmup, 1-step gradient updates, periodic evaluation, model checkpointing, and SAC baseline comparison support (EXP-01, EXP-03).
4. Unit and integration tests in `tests/test_logger.py` and `tests/test_train.py`.

Purpose: Provide a production-grade, CLI-driven training and evaluation harness ready to reproduce benchmark results across MuJoCo environments.
Output: `src/tqc/logger.py`, `src/tqc/evaluate.py`, `src/tqc/train.py`, and test suites.
</objective>

  <action>
    1. Create `src/tqc/evaluate.py`:
       - `evaluate_policy(agent, env, n_episodes: int = 10, deterministic: bool = True) -> Tuple[float, float]`:
         - Runs `n_episodes` without gradient tracking (`torch.no_grad()`).
         - Uses deterministic actions from policy ($a = \tanh(\mu)$).
         - Accumulates undiscounted episodic returns.
         - Returns `(mean_return, std_return)`.
    2. Create `src/tqc/train.py`:
       - `train_tqc(...)`:
         - Initializes training environment and evaluation environment with seeds.
         - Instantiates `ReplayBuffer` (capacity $10^6$), `TQCAgent`, and `MetricsLogger`.
         - Executes warm-up steps (e.g. 10,000 steps sampling random actions `env.action_space.sample()`).
         - Main training loop up to `total_timesteps`:
           - Steps env with policy action ($a \sim \pi(\cdot|s)$).
           - Adds transition $(s, a, r, s', \text{terminated})$ to replay buffer.
           - Executes 1 gradient update step `agent.update(replay_buffer, batch_size=256)` per env step.
           - Evaluates policy every `eval_freq` steps (default 5,000 or 10,000 steps), records metrics, and saves `best_model.pt`.
           - Saves periodic checkpoints at specified intervals.
         - Exposes CLI interface (`argparse`): `--env-id`, `--seed`, `--total-timesteps`, `--eval-freq`, `--device`, `--drop-top`, `--log-dir`, `--algo` (`tqc` or `sac`).
    3. Write integration tests in `tests/test_train.py`:
       - Run a fast end-to-end integration test (e.g., 50-100 steps on `InvertedPendulum-v4` or `HalfCheetah-v4` with tiny buffer) asserting:
         - Environment steps and buffer population work seamlessly.
         - Agent `update()` executes without gradient/device errors.
         - Periodic evaluation returns valid float metrics.
         - Logger writes files to output directory.
  </action>
